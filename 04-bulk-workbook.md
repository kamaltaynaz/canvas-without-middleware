# 04. The bulk workbook: rows, a menu and safe re-runs

*Paste this when the core is built and I have approved it. Use it for the bulk method and for collect-then-batch.*

---

Build the workbook I will run from: one permanent spreadsheet, one tab per term, one row per course, and a custom menu.

## Build these

1. **Tab set-up.** A menu item that prepares a tab: headers, plain-text formats, dropdowns for the status and choice columns, protection on the script's output columns, and a frozen header row. Safe to run again on an existing tab.
2. **A new-term item.** Asks for the term code, checks it against the pattern in the spec, creates the tab and sets it up. The run commands refuse a tab whose name is not a valid term.
3. **The row runner.** For each row whose status says to process it:
   - read the inputs and the evidence columns;
   - run each step in order, skipping any whose evidence is present;
   - write each step's evidence as soon as that step succeeds, not at the end of the row;
   - write warnings to the warnings column and carry on;
   - on a failure that must stop the row, write the error and leave every earlier result in place;
   - when all steps are complete, set the status to done.
4. **Re-run by difference.** When I add something to a finished row (a tool, a copy source, an instructor who was "to be confirmed") and set it back to ready, only the new piece is done. Keep a snapshot column where a step needs to know what it did last time.
5. **Menu commands.** Run all pending on this tab. Run the selected rows. Dry run the selected rows. Show the current environment. Switch environment.
6. **The environment indicator.** A cell on every term tab that shows the active environment, refreshed when the sheet opens and when I switch. Make production visually unmistakable.
7. **Pause and resume.** Stop cleanly before the run-time limit, save the place, and schedule the run to continue. Never start a second run while one is in progress. See `examples/PauseAndResume.gs`.
8. **A summary email to me** at the end of a run: rows done, rows with warnings, rows that failed and why. For a run that paused and resumed, the summary covers the whole tab.
9. **Rehearsal reset,** for test and beta only. It refuses in production. Before deleting a course, it renames the section IDs and then the course ID, so the same IDs can be used again. Include a recovery command for courses already deleted with their IDs still reserved.
10. **An in-sheet help tab** generated by the script: what each column means, the statuses, and the menu. Mirror it in `docs/USAGE.md`.

## If I chose "collect, then batch"

Add a Google Form whose responses arrive in a tab of this workbook, and a menu command that copies new, complete responses into the term tab as rows with a status that waits for my review. **No Canvas token is involved in collecting.** Nothing is built until I mark rows ready and run them. Use `05-live-form.md` only for its advice on designing the form.

## Check with me before you call it finished

- Run a dry run of five varied rows and read it with me: a single section, several sections shared, several sections separate, an unknown instructor, and a row with every option switched on.
- Run those five for real in the test Canvas. Show me each course.
- Run the same five again. Nothing new should be created. Show me the log proving each step was skipped.
- Change one thing on a finished row, set it to ready and run. Only that thing should happen.
- Reset the tab and run it a third time, to prove the IDs were freed.
